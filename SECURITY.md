# Security and execution limits

The primary `strengthen` command executes repository and generated test code in
Docker by default. It requires a clean committed input and an output directory
outside it; accepted tests are exported as independent patches, never applied.
The image must contain the target dependencies. Model calls have an application
call limit, not a hard monetary cap. Traces include source and generated code.
`test-prepare` and `test-score` make no model calls. `test-study` defaults to a
dry run; `--live` is required to start generation. Shared conservative token
reservations stop before another call when reported usage is unknown or the
allowance cannot cover it. SDK retries can leave additional billing unreported;
these are not Azure account spending limits. Interrupted in-flight work is kept
visible and never silently regenerated by the scorer.

The CLI commands use a local Docker image by default and refuse to silently fall
back to host execution.
Images must be built/inspected by the operator. Tags are resolved to an immutable
image ID at the start of a CLI run.

Every pytest invocation receives a fresh copied repository, excluding Git metadata,
environment files and symlinks. Containers have no host bind mounts or Docker socket,
no network, no inherited host credentials, no Linux capabilities, a non-root user,
a read-only root filesystem, 1 GiB memory, two CPUs, 128 processes and 512 MiB
temporary storage. Inputs are limited to 32 MiB. Timeout cleanup removes the
specific container and its child processes.

These are practical containment controls, not a formal sandbox security audit.
Docker itself and its images remain trusted. Malicious repository code can tamper
with its own pytest evidence, and source/tool checks do not prove semantic safety.
Full traces contain repository code; treat them as sensitive on private projects.
Only submit repositories you are authorized to send to the configured model provider.

`--unsafe-local` explicitly opts out of container execution and should only be
used with trusted fixtures. Library-level `run_pytest` defaults to local
execution for trusted fixtures; callers must use `execution_image` for isolation.

Never commit `.env`, API keys, private traces or virtual environments. Credentials
belong only in the host-side model client. Rotate any key previously exposed in
a chat, screenshot, terminal history or committed file. A later ignore rule does
not revoke a leaked key.

There is no automatic patch application, GitHub publication, deployment or merge.
Review the patch and the validation scope before applying it.
